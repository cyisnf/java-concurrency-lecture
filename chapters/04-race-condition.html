4  競合状態と排他制御

4.1 概要

ある変数を複数のスレッドから同時に更新した際に、更新の一部が失われることがあります（競合状態）。

一度に1つのスレッドだけがその処理を実行できるようにすることで、これを防ぐことができます（排他制御）。

4.2 問題の確認

  • 3つのスレッドがあり、変数 c を共有しているとします。
  • 各スレッドは、10000回ずつ変数 c の値をインクリメント（c++）します。
  • 正しく動けば、最終的な c は 30000 になるはずです。
Count.java（排他制御なし）
public class Count {
    int c = 0;  // 3つのスレッドが共有する変数

    public static void main(String[] args) throws InterruptedException {
        Count count = new Count();
        CounterThread t1 = new CounterThread(count);
        CounterThread t2 = new CounterThread(count);
        CounterThread t3 = new CounterThread(count);
        t1.start();
        t2.start();
        t3.start();

        // 3つのスレッドがすべて終わるまで待つ（join は第6章で詳しく説明）
        t1.join();
        t2.join();
        t3.join();
        System.out.println("最終結果: " + count.c);  // 期待している値は30000
    }
}

class CounterThread extends Thread {
    Count count;

    public CounterThread(Count count) {
        this.count = count;
    }

    public void run() {
        for (int i = 0; i < 10000; i++) {
            count.c++;  // 共有変数を1増やす
        }
    }
}

何度か実行すると、結果が30000未満になることがあります。

4.3 なぜ値が失われるのか

count.c++; は、実際には次の3つの操作に分かれて実行されます。

  1. 読み込み：変数 c の値を読み込む。
  2. 計算：読み込んだ値に1を足す。
  3. 書き込み：計算結果を変数 c に書き込む。

あるスレッドが1〜3を終える前に、別のスレッドが割り込むと、次のように更新が失われます（c の初期値を10とします）。

2つのスレッドがそれぞれ1回ずつ足したのに、結果的に c は1しか増えていません。

重要共有変数の書き換えには必ず注意する

スレッドの利点は、同じ変数を共有できることです。しかし、共有変数を複数のスレッドで書き換えるときは常に、正しく対処しなければ、この問題が起こりうると考えてください。

4.4 対処法1：synchronizedブロック

Javaのすべてのオブジェクトは、ロック（鍵）を1つずつ持っています。

  • スレッドは synchronized (オブジェクト) { … } と記述されたブロックに入るときに、そのオブジェクトのロックを取得します。
  • そして、ブロックを出るときには、ロックを解放します。
  • あるスレッドがロックを持っている間、他のスレッドは同じロックを取得できず、ロックが解放されるまで待たされます。

これを使って、c++ の操作を「同時に1つのスレッドだけに行わせる」ことができます。

Count.java（synchronizedブロック版）の変更箇所
public class Count {
    int c = 0;

    // c を1増やす処理を、Count クラスのメソッドにまとめる
    public void inc() {
        synchronized (this) {  // この Count オブジェクトのロックを取得
            c++;               // 読み込み・計算・書き込みを1つのスレッドだけが行う
        }                      // ここでロックを解放
    }
    // main メソッドは変更無し
}

class CounterThread extends Thread {
    // …（フィールドとコンストラクタは変更無し）
    public void run() {
        for (int i = 0; i < 10000; i++) {
            count.inc();  // c++ の代わりに inc() を呼ぶ
        }
    }
}

これで、何度実行しても最終結果は必ず30000になります。

ロックを持つスレッドが「読み込み・計算・書き込み」を終えてからロックを解放するため、図 4.1 のような競合は発生しません。

このように、ある処理を同時に1つのスレッドしか実行できないようにする制御を排他制御と呼びます。

警告排他制御は「すべての」アクセスに必要

排他制御によって割り込みを防げるのは、同じオブジェクトのロックを取得しようとするスレッドだけです。

synchronized を使わず（＝ロックを取得しようとせず）に同じ変数を読み書きする処理があると、その処理は割り込むことができてしまいます。

4.5 対処法2：synchronizedメソッド

メソッド全体を排他制御したいときは、メソッドの宣言に synchronized を付けます。

public synchronized void inc() {
    c++;
}

これは、メソッドの中身全体を synchronized (this) { … } で囲んだのと同じ意味です。

メソッド全体を排他制御すると、本来は排他制御の必要がない処理まで1つのスレッドしか実行できなくなり、処理が遅くなることがあります。

排他制御の範囲は必要な部分だけに絞るのが基本です。

4.6 2つの方法の比較

synchronizedブロック synchronizedメソッド
ロックの対象 任意のオブジェクト this
排他制御の範囲 必要な部分だけ メソッド全体
書きやすさ やや長い 簡潔

4.7 補足：スレッドの識別番号

各スレッドには一意の識別番号（スレッドID）があり、getId() で取得できます。

スレッドIDは正の long 型の値で、そのスレッドが存在する間は変わりません。スレッドの終了後は、同じ値が再利用されることがあります。

どのスレッドが処理を行ったのかを確かめたいときは、run() の中に次を追加するとよいでしょう。

System.out.println(getId() + ":" + count.c);

※ Java 19以降では、getId() の代わりに threadId() を使うことが推奨されています。

練習問題1：スレッド安全なキュー

次のキュー（IntQueue）を、複数のスレッドから同時に操作しても正しく動くように変更してください。

仕様

  • キューには正の整数だけを入れられる。
  • tail は現在の末尾の位置を表す。キューが空のときは tail = -1 とする。
  • enqueue（追加）用のスレッドを2つ、dequeue（取り出し）用のスレッドを2つ、並行に動かす。
IntQueue.java
public class IntQueue {
    final int SIZE = 10;
    private int[] values = new int[SIZE];
    private int tail = -1;  // 末尾の位置（空のときは -1）

    boolean enqueue(int data) {
        if (data <= 0) {
            return false;           // 負の値は受け付けない
        }
        if (tail == SIZE - 1) {
            return false;           // 満杯
        }
        pause();                    // 競合を起こりやすくするための休止（下の説明を参照）
        tail++;
        values[tail] = data;
        System.out.println("enqueue :" + data + " tail:" + tail);
        return true;
    }

    int dequeue() {
        if (isEmpty()) {
            return -1;              // 空
        }
        pause();                    // 競合を起こりやすくするための休止
        int data = values[0];
        for (int i = 0; i < SIZE - 1; i++) {
            values[i] = values[i + 1];  // 要素を1つずつ前に詰める
        }
        tail--;
        System.out.println("dequeue :" + data + " tail:" + tail);
        return data;
    }

    boolean isEmpty() {
        return (tail == -1);
    }

    // 1ミリ秒だけ休止する（キューの機能には不要。競合を観察しやすくするための処理）
    static void pause() {
        try {
            Thread.sleep(1);
        } catch (InterruptedException e) {
        }
    }

    public static void main(String[] args) {
        IntQueue q = new IntQueue();
        new EnQueueThread(q).start();
        new EnQueueThread(q).start();
        new DeQueueThread(q).start();
        new DeQueueThread(q).start();
    }
}

class EnQueueThread extends Thread {
    IntQueue q;

    public EnQueueThread(IntQueue q) {
        this.q = q;
    }

    public void run() {
        for (int i = 0; i < 100; i++) {
            int data = (int) (Math.random() * 100 + 1);  // 1〜100の乱数
            q.enqueue(data);
        }
    }
}

class DeQueueThread extends Thread {
    IntQueue q;

    public DeQueueThread(IntQueue q) {
        this.q = q;
    }

    public void run() {
        for (int i = 0; i < 100; i++) {
            q.dequeue();
        }
    }
}
ノートpause() を入れている理由

pause() は、tail を確かめてから書き換えるまでの間に1ミリ秒休み、その間に他のスレッドが割り込む機会を増やします。

pause() がなくても割り込みは起こりえますが、めったに起こらないため、何度実行しても問題が見えないことがあります。

pause() は消さずに課題に取り組んでください。

余裕があれば、pause() の呼び出しを消して実行し、結果を比べてみましょう。例外が出なくなっても、プログラムが正しくなったわけではありません。

ヒントヒント（最初は自力でやってみること。クリックで表示）
  • 「tail の確認」から「tail・values の書き換えと表示」までを、割り込まれない1つのまとまりにします。
  • enqueue() と dequeue() の両方に、同じロックで排他制御を追加します（セクション 4.5）。

練習問題2：ATMによる送金

printMoney() と move() の中身を書き、口座間でお金を移動するプログラムを完成させてください。

仕様

  • 口座は100個あり、各口座の初期残高は10万円とする。
  • 顧客30人（Customer スレッド30個）が同時にATMを操作する。
  • 各顧客は、0〜9ミリ秒に1回、ランダムに選んだ口座からランダムに選んだ口座へ、ランダムな金額（0〜9999円）を移動する。これを1人1000回行う。
  • 全員の操作が終わった後、全口座の残高と総額を printMoney() で表示し、総額が 10万円 × 100口座 = 1000万円のままであることを確認する。
ATM.java
public class ATM {
    static int SIZE = 100;
    int[] account;

    public ATM() {
        account = new int[SIZE];
        for (int i = 0; i < SIZE; i++) {
            account[i] = 100000;  // 初期残高10万円
        }
    }

    void printMoney() {
        // ここを記述：各口座の残高と総額を表示する
    }

    void move(int from, int to, int money) {
        // ここを記述：口座 from から口座 to へ money 円を移動する
    }

    public static void main(String[] args) {
        ATM atm = new ATM();
        for (int i = 0; i < 30; i++) {
            new Customer(atm).start();
        }
    }
}

class Customer extends Thread {
    ATM atm;

    public Customer(ATM atm) {
        this.atm = atm;
    }

    public void run() {
        for (int i = 0; i < 1000; i++) {
            int from = (int) (Math.random() * ATM.SIZE);
            int to = (int) (Math.random() * ATM.SIZE);
            int money = (int) (Math.random() * 10000);
            atm.move(from, to, money);
        }
        atm.printMoney();  // 各顧客が操作を終えるたびに表示（最後の表示が最終結果）
    }
}
ヒントヒント（最初は自力でやってみること。クリックで表示）
  • move()：出金と入金を書き、2つを割り込まれない1つのまとまりにします。
  • printMoney()：全口座を表示しながら総額を求めます。この処理全体を、move() と同じオブジェクトのロックで守ります。
