9  総合演習

9.1 概要

これまでに学んだ内容を組み合わせて、2つの課題に取り組みましょう。

どちらの課題も、プログラムが正しく動いているかを確かめる仕組みが、配布するプログラムに含まれています。 必ず「OK」と表示されることを確認してから、結果をまとめてください。

提出物（提出方法は授業で指示します）

  1. 作成したプログラムのソースファイル
  2. 実行結果をまとめた表と考察が記されたPDF

課題1：整理番号の発行

銀行や役所の窓口では、来た人に整理番号を配ります。 5つの窓口（スレッド）が、1台の番号発行機（Ticket オブジェクト）を共有して、整理番号を発行するプログラムを作成してください。

仕様

  • 番号は1から始まる連番とする。
  • 窓口は5つあり、各窓口が10000枚ずつ、合計50000枚の番号を発行する。
  • 同じ番号を2回以上発行してはならない（重複なし）。
  • 発行されない番号があってはならない（欠番なし）。
    つまり、1〜50000の番号が1回ずつ発行されなければならない。
Ticket.java
public class Ticket {
    static final int WINDOWS = 5;          // 窓口の数
    static final int PER_WINDOW = 10000;   // 1つの窓口が発行する枚数
    int next = 1;  // 次に発行する番号

    int issue() {
        // ここを記述：next の値を返し、next を1増やす
    }

    public static void main(String[] args) throws InterruptedException {
        Ticket ticket = new Ticket();
        Window[] windows = new Window[WINDOWS];
        for (int i = 0; i < WINDOWS; i++) {
            windows[i] = new Window(ticket);
            windows[i].start();
        }
        for (int i = 0; i < WINDOWS; i++) {
            windows[i].join();  // すべての窓口の発行が終わるまで待つ
        }
        check(windows);
    }

    /** 発行された番号に、重複と欠番がないかを調べる（変更しないこと） */
    static void check(Window[] windows) {
        int total = WINDOWS * PER_WINDOW;    // 発行した枚数
        int[] times = new int[total + 1];    // times[k] は、番号 k が発行された回数
        int outOfRange = 0;                  // 1〜total の範囲外の番号の数
        for (Window w : windows) {
            for (int number : w.issued) {
                if (1 <= number && number <= total) {
                    times[number]++;
                } else {
                    outOfRange++;
                }
            }
        }
        int duplicated = 0;  // 2回以上発行された番号の数
        int missing = 0;     // 1回も発行されなかった番号の数
        for (int k = 1; k <= total; k++) {
            if (times[k] >= 2) duplicated++;
            if (times[k] == 0) missing++;
        }
        System.out.println("発行枚数: " + total + "  重複した番号: " + duplicated
                + "  欠番: " + missing + "  範囲外: " + outOfRange);
        System.out.println((duplicated == 0 && missing == 0 && outOfRange == 0) ? "OK" : "NG");
    }
}

class Window extends Thread {
    Ticket ticket;
    int[] issued = new int[Ticket.PER_WINDOW];  // この窓口が発行した番号の記録

    public Window(Ticket ticket) {
        this.ticket = ticket;
    }

    public void run() {
        for (int i = 0; i < Ticket.PER_WINDOW; i++) {
            issued[i] = ticket.issue();
        }
    }
}

各窓口は、発行した番号を自分専用の配列 issued に記録します。すべての窓口が終わった後、check() が全窓口の記録を集めて、重複と欠番の数を表示します。

手順

  1. 排他制御なし：issue() の中身を書き、5回実行して、重複した番号と欠番の数を記録する。
  2. synchronized 版：issue() を synchronized メソッドにして、5回実行する。
  3. volatile 版：synchronized を外し、代わりに変数 next に volatile を付けて、5回実行する。
  4. AtomicInteger 版：変数 next を java.util.concurrent.atomic.AtomicInteger 型に変え、synchronized も volatile も使わずに issue() を書き直して、5回実行する。
  5. 結果を、次の3つの表にまとめる。各欄には、check() が表示した値をそのまま書く。「範囲外」は、issue() を正しく書けていれば0になるため、記録しなくてよい。

考察

  1. 排他制御なしの場合に、重複や欠番が生じる理由を説明せよ（セクション 4.3）。
  2. volatile 版で重複や欠番を防げるかどうかを、実行結果に基づいて答えよ。また、その理由を「原子性」と「可視性」という言葉を使って説明せよ（セクション 5.5）。
警告1回の実行だけで判断しない

競合状態は、実行のたびに起こったり起こらなかったりします。排他制御なしでも、たまたま「OK」になることがあります。1回「OK」になっただけでは、正しいプログラムとは言えません。

ヒントヒント（最初は自力でやってみる。クリックで表示）
  • 手順1は、next の値を別の変数に取っておき、next を1増やしてから、取っておいた値を返します。return next++; と1行で書いても同じ意味です。
  • 手順3で volatile を付けると、どの操作が保証されて、どの操作が保証されないのかを、表 5.1 で確かめてください。
  • 手順4では、AtomicInteger の getAndIncrement() を使います。このメソッドは、1増やす前の値を返します。incrementAndGet()（1増やした後の値を返す）を使うと、番号が2から始まってしまい、「範囲外」と「欠番」が1つずつ表示されます。

課題2：行列の積の並列化

N行N列の2つの行列 \(A\)、\(B\) の積 \(C = A \times B\) を求めるプログラムを、並列処理で高速化してください。

行列の積 \(C\) の \(i\) 行 \(j\) 列の要素 \(c_{ij}\) は、\(A\) の \(i\) 行目と \(B\) の \(j\) 列目の、対応する要素どうしの積の和です。

\[ c_{ij} = a_{i0} b_{0j} + a_{i1} b_{1j} + \cdots + a_{i,N-1} b_{N-1,j} = \sum_{k=0}^{N-1} a_{ik} b_{kj} \]

\(C\) の各要素は、他の要素の計算結果を使わずに、それぞれ独立に計算できます。そのため、行列の積は並列処理に向いています（セクション 8.5）。

次の Matrix.java は、\(C\) の要素を1つずつ順番に計算する逐次版です。この中の SequentialMultiply クラスを、並列に計算するクラスに置き換えます。

Matrix.java（逐次版）
public class Matrix {
    static final int N = 1300;  // 行列の大きさ（N行N列）

    public static void main(String[] args) throws InterruptedException {
        int num = (args.length > 0) ? Integer.parseInt(args[0]) : 1;  // スレッド数
        int[][] a = randomMatrix(N);
        int[][] b = randomMatrix(N);

        long start = System.currentTimeMillis();
        // ここから行列の積の計算の呼び出し
        SequentialMultiply mm = new SequentialMultiply(a, b);
        int[][] c = mm.getResult();
        long end = System.currentTimeMillis();

        System.out.println("スレッド数: " + num + "  結果: " + (check(a, b, c) ? "OK" : "NG")
                + "  処理時間: " + (end - start) + " ミリ秒");
    }

    /** 各要素が0〜9の乱数である n行n列 の行列を作る */
    static int[][] randomMatrix(int n) {
        int[][] m = new int[n][n];
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                m[i][j] = (int) (Math.random() * 10);
            }
        }
        return m;
    }

    /**
       c が a × b と等しいかを調べる（変更しないこと）
       乱数で作ったベクトル x について、c × x と a × (b × x) が等しいかを比べる
    */
    static boolean check(int[][] a, int[][] b, int[][] c) {
        int n = a.length;
        long[] x = new long[n];
        for (int i = 0; i < n; i++) {
            x[i] = (long) (Math.random() * 1000);
        }
        long[] left = times(c, x);             // c × x
        long[] right = times(a, times(b, x));  // a × (b × x)
        for (int i = 0; i < n; i++) {
            if (left[i] != right[i]) {
                return false;
            }
        }
        return true;
    }

    /** 行列 m とベクトル v の積を求める（check から使う） */
    static long[] times(int[][] m, long[] v) {
        int n = m.length;
        long[] result = new long[n];
        for (int i = 0; i < n; i++) {
            for (int k = 0; k < n; k++) {
                result[i] += m[i][k] * v[k];
            }
        }
        return result;
    }
}

/**
   行列の積を求める（逐次）
*/
class SequentialMultiply {
    private int[][] a;
    private int[][] b;
    private int[][] c;  // 計算結果 c = a × b

    /** コンストラクタから自動で計算が実行される */
    SequentialMultiply(int[][] a, int[][] b) {
        this.a = a;
        this.b = b;
        int n = a.length;
        c = new int[n][n];
        multiply();
    }

    /** c の各要素を計算する */
    private void multiply() {
        int n = a.length;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                int sum = 0;
                for (int k = 0; k < n; k++) {
                    sum += a[i][k] * b[k][j];  // a の i 行目と b の j 列目の積の和
                }
                c[i][j] = sum;
            }
        }
    }

    /** 計算結果を得るメソッド */
    int[][] getResult() {
        return c;
    }
}

check() は、計算した \(C\) が \(A \times B\) と等しいかを、短い時間で調べるメソッドです。1つでも誤った要素があれば、「NG」と表示されます。

スレッド数は、セクション 8.3 と同じく、コマンドライン引数で指定します。

$ java Matrix 4      # 4スレッドで実行する

並列版の構成

並列版は、役割の異なる次の2つのクラスで作ります。

main メソッドの「ここから行列の積の計算の呼び出し」の部分は、次のように1行だけ変更します。

Matrix.java（並列版）の main メソッドの変更箇所
        // ここから行列の積の計算の呼び出し
        ParallelMultiply mm = new ParallelMultiply(a, b, num);  // SequentialMultiply を置き換える

SequentialMultiply クラスは削除し、代わりに次の2つのクラスを書きます。「ここを記述」の部分を完成させてください。

Matrix.java（並列版）の ParallelMultiply と MultiplyThread
/**
   行列の積を求める（並列）
   仕事を分けてスレッドに渡し、すべてのスレッドの終了を待つ
*/
class ParallelMultiply {
    private int[][] c;  // 計算結果 c = a × b（全スレッドで共有する）

    ParallelMultiply(int[][] a, int[][] b, int num) throws InterruptedException {
        int n = a.length;
        c = new int[n][n];
        // ここを記述：
        //   (1) C の行をスレッド数 num で等分し、MultiplyThread を num 個作って起動する
        //   (2) すべてのスレッドの終了を待つ
    }

    /** 計算結果を得るメソッド */
    int[][] getResult() {
        return c;
    }
}

/**
   割り当てられた範囲の行だけを計算するスレッド
*/
class MultiplyThread extends Thread {
    int[][] a;
    int[][] b;
    int[][] c;
    int start;  // 担当する行の始め（この行を含む）
    int end;    // 担当する行の終わり（この行を含まない）

    MultiplyThread(int[][] a, int[][] b, int[][] c, int start, int end) {
        this.a = a;
        this.b = b;
        this.c = c;
        this.start = start;
        this.end = end;
    }

    public void run() {
        // ここを記述：start 行目から end-1 行目までの、c の要素を計算する
    }
}
ノートこの課題では排他制御は不要

全スレッドが同じ配列 c に書き込みますが、このプログラムでは synchronized などの排他制御は必要ありません。排他制御を加えると、かえって遅くなります。なぜ不要なのかは、考察1で考えましょう。

仕様

  • 行列の積を正しく（「OK」と表示されるように）計算する。
  • check() と randomMatrix() は変更しない。
  • 排他制御（synchronized）は使わない。

手順

  1. nproc などで、使用している計算機の論理プロセッサ数を確認する（セクション 8.2）。
  2. 逐次版を3回実行し、処理時間とその平均を 表 9.6 に記録する。
  3. 並列版：main メソッドを変更し、ParallelMultiply と MultiplyThread の「ここを記述」の部分を完成させる。
  4. スレッド数を1, 2, 4, 8, 16, 32 と変えて、それぞれ3回ずつ実行し、処理時間とその平均を 表 9.7 に記録する。
  5. スレッド数ごとに、次の2つの値を計算し、表 9.8 に記録する。小数第2位まで求める。
    • 速度向上率：逐次版の平均（表 9.6）を、並列版の平均（表 9.7）で割った値。並列版が逐次版の何倍速いかを表す。
    • 並列化効率：速度向上率を、スレッド数で割った値。理想は1.00で、これは「スレッド数を2倍にすると、処理時間がちょうど半分になる」場合にあたる。

考察

  1. 全スレッドが同じ配列を扱っているのに、排他制御が不要である理由を説明せよ。配列 c と、配列 a・b のそれぞれについて答えること（セクション 4.3）。
  2. スレッド数を増やしたとき、速度向上率と並列化効率はどのように変化したか。並列化効率が1.00に届かない理由を考察せよ（セクション 8.2、セクション 8.5）。
ヒントヒント（最初は自力でやってみる。クリックで表示）
  • ParallelMultiply の (1)：セクション 8.3 の main メソッドで、担当範囲を計算してスレッドを起動している部分が参考になります。各スレッドには、ParallelMultiply が作った配列 c をそのまま渡します。
  • MultiplyThread の run()：逐次版の multiply() とほぼ同じです。いちばん外側のループで、i を 0〜n-1 ではなく、start〜end-1 の範囲で回します。
  • 担当する行の端数：1300 は、例えば 8 では割り切れません。最後のスレッドに端数の行も担当させてください（セクション 8.3）。端数を担当させないと「NG」と出力されます。
  • 終了を待つ：計算結果を main メソッドに返す前に、すべてのスレッドの join() を呼びます（セクション 6.2）。start() を呼ぶループと join() を呼ぶループは、分けて書いてください。同じループの中で start() の直後に join() を呼ぶと、1つのスレッドが終わるまで次のスレッドが起動されず、逐次版と同じ速さになります。
