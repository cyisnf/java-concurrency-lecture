8  並列処理による高速化

Javaのスレッドは、使えるコアが複数あれば自動的に並列に実行されます。書き方はこれまでの並行プログラミングと同じです。この章では、スレッド数を増やすと実行時間がどれだけ短くなるかを、実際に測って確かめます。

8.1 CPU（コア）数の確認

まず、使っているコンピュータが同時にいくつの処理を実行できるかを確認します。Linuxでは次のコマンドで確認できます。

$ nproc                              # 同時に実行できる処理の数（論理プロセッサ数）
8
$ grep processor /proc/cpuinfo       # 論理プロセッサの一覧
processor       : 0
processor       : 1
（中略）
processor       : 7

Javaのプログラムの中からは、Runtime.getRuntime().availableProcessors() で同じ値を取得できます。

上の例の計算機では、OSから8個の論理プロセッサが見えています。したがって、8スレッドまでは同時に実行できます。

ノート物理コアと論理プロセッサ

Intel製CPUなどには、1つの物理コアを2つの論理プロセッサに見せる技術（ハイパースレッディング）があります。たとえば「4コア8スレッド」のCPUは、物理コアは4つですが、OSからは8個の論理プロセッサとして見えます。

論理プロセッサは物理コアの計算部分を共有するため、物理コア数を超えてスレッドを増やしても、速度はあまり伸びないことが多い点に注意してください。

8.2 サンプル：配列の要素を分担して増やす

100万個の要素をもつ配列の各要素を、10000回ずつ1増やすプログラムです。コマンドライン引数でスレッド数を指定し、配列をスレッド数で等分して、各スレッドに担当させます。

ParaSample.java
public class ParaSample {
    static final int SIZE = 1000000;
    int[] array = new int[SIZE];

    public static void main(String[] args) throws InterruptedException {
        int num = Integer.parseInt(args[0]);  // スレッド数
        ParaSample ps = new ParaSample();
        ParaSampleThread[] threads = new ParaSampleThread[num];

        long startTime = System.currentTimeMillis();  // 計測開始

        // 配列を num 個に分け、各スレッドに担当範囲 [start, end) を割り当てる
        for (int i = 0; i < num; i++) {
            int start = SIZE / num * i;
            int end = (i == num - 1) ? SIZE : SIZE / num * (i + 1);  // 最後のスレッドは端数も担当
            threads[i] = new ParaSampleThread(start, end, ps);
            threads[i].start();
        }

        // すべてのスレッドの終了を待つ
        for (int i = 0; i < num; i++) {
            threads[i].join();
        }

        long endTime = System.currentTimeMillis();    // 計測終了
        System.out.println("処理時間: " + (endTime - startTime) + " ミリ秒");
    }
}

class ParaSampleThread extends Thread {
    int start;
    int end;
    ParaSample ps;

    public ParaSampleThread(int start, int end, ParaSample ps) {
        this.start = start;
        this.end = end;
        this.ps = ps;
    }

    public void run() {
        for (int i = 0; i < 10000; i++) {
            for (int j = start; j < end; j++) {
                ps.array[j]++;  // 担当範囲の要素だけを増やす
            }
        }
    }
}

各スレッドは配列の別々の範囲だけを書き換えるため、同じ要素を複数のスレッドが触ることはありません。そのため、第5章の排他制御は不要です。

※ 担当範囲の終わりは、最後のスレッドだけ SIZE にしています。たとえば3スレッドの場合、1000000 ÷ 3 の余り（1要素）が、どのスレッドにも割り当てられずに残るのを防ぐためです。

8.3 実行時間の測り方

方法1：プログラムの中で測る（8.2節のサンプルで使っている方法）

long startTime = System.currentTimeMillis();
// 計測したい処理
long endTime = System.currentTimeMillis();
System.out.println((endTime - startTime) + " ミリ秒");

方法2：time コマンドで測る（JVMの起動時間も含めた、プログラム全体の時間）

$ time java ParaSample 1 > /dev/null
real    0m5.886s
user    0m6.210s
sys     0m1.472s

$ time java ParaSample 2 > /dev/null
real    0m2.988s
user    0m5.863s
sys     0m0.015s

$ time java ParaSample 3 > /dev/null
real    0m2.034s
user    0m5.849s
sys     0m0.016s
項目 意味 スレッドを増やすと
real 開始から終了までの実際の経過時間 短くなる（並列化の効果はここに表れる）
user CPUがプログラムの処理に使った時間（全コアの合計） ほとんど変わらない
sys CPUがOSの処理（入出力など）に使った時間 処理内容による

user がほとんど変わらないのは、仕事の総量が変わらないからです。半分ずつの仕事を2人で分担しても、1人で全部やっても、仕事の総量は同じなのと同じ理屈です。

> /dev/null は、プログラムの出力を画面に表示せずに捨てる指定です。画面表示（入出力）にかかる時間を除いて、計算の時間を測りたいときに使います。

8.4 並列処理に向くプログラム、向かないプログラム

向いているプログラム 向いていないプログラム
各処理が互いに独立している（他の処理の結果を待たない） 各処理が互いに依存している（他の処理の結果を待つ必要がある）
各スレッドの仕事量がほぼ等しい 各スレッドの仕事量に大きな偏りがある
例：8.2節のように、配列を範囲で分けて処理する 例：前の計算結果を使って次の計算をする処理

依存関係があると、待ち時間が生じて速度が伸びません。仕事量に偏りがあると、全体の終了時刻は最も遅いスレッドで決まります。また、プログラムの中に並列化できない部分があると、スレッドをいくら増やしてもその部分の時間は短くなりません（これをアムダールの法則と呼びます）。

並列化を考えるときは、まず他の処理から独立して実行できる部分を探すことから始めましょう。
