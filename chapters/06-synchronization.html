6  スレッドの同期

6.1 概要

同期とは、複数のスレッドの間で、処理のタイミングを合わせることです。

  • どのスレッドをいつ実行するかは、基本的にOSなどのシステムが決めます。
  • しかし、join(), wait(), notify() を使うと、「ある処理が終わってから、この処理を行う」というような処理の前後関係を、プログラムの側で指定できます。

6.2 join：スレッドの終了を待つ

join() は指定したスレッドが終了するまで待つメソッドです。

処理の流れを 図 6.1 に示します。

サンプル：カウントと終了表示

後述する手順にしたがって、次のコードを実行してください。

JoinTest.java
public class JoinTest extends Thread {

    public void run() {
        for (int i = 0; i < 10; i++) {
            System.out.println(i);
        }
    }

    public static void main(String[] args) {
        JoinTest t = new JoinTest();
        t.start();

        /* 手順2で、このコメントを外す
        try {
            t.join();  // スレッド t が終わるまで、メインスレッドはここで待つ
        } catch (InterruptedException e) {
        }
        */

        System.out.println("END");
    }
}

手順

  1. 何度か実行して、カウントが終わる前にENDが表示されることを確認する。
  2. コメントを外して再度実行し、ENDが必ず最後に表示されることを確認する。

6.3 wait：条件が整うまで待つ

  • wait() は、他のスレッドから通知が来るまで待つメソッドです。
  • notify(), notifyAll() は、通知を送るメソッドです。

(a) notify による通知

3つのスレッドが、同じオブジェクト obj を使って、wait(), notify() を呼ぶ場合の流れを 図 6.2 に示します。

手順3の notify() では、待機中の2つのスレッドのうち1つだけ（この図ではスレッド1）が起こされます。どちらが起こされるかはシステムが決めるため、スレッド3が起こされる場合もあります。

(b) notifyAll による通知

続いて、notifyAll() について、同様の流れを 図 6.3 に示します。

notifyAll() では、待機中のスレッドがすべて起こされます。ただし、ロックを持てるのは一度に1つだけなので、実際に再開するのは1つずつです。

重要なポイント

  • wait(), notify(), notifyAll() は、そのオブジェクトのロックを持っている状態でしか呼べません。
    （つまり、 synchronized ブロック／メソッドの中でしか呼べない）
  • wait() を呼んだスレッドがロックを手放すことによって、その間に他のスレッドが synchronized の中に入れるようになります。
  • notify() で起こされたスレッドは、ロックをもう一度取得できてから、wait() の次の行から処理を再開します。

サンプル：上限と下限のあるカウンタ

以下は、2つのスレッドが、変数 n をそれぞれ1000回ずつインクリメント（n++）またはデクリメント（n--）するプログラムです。

ただし、次のようにして、常に n の値が \([0, 10]\) の範囲に保たれるようにします。

  • n が10のときに、さらに増やそうとしたら、wait() で待つ
  • n が0のときに、さらに減らそうとしたら、wait() で待つ
  • 増減に成功したら notify() を呼び、待っている相手のスレッドを起こす
WaitNotifyTest.java
public class WaitNotifyTest {
    int n = 0;

    synchronized void inc() {
        while (n == 10) {  // 上限に達している間は待つ（if ではなく while）
            System.out.println("nが10なので、加算を待機");
            try {
                wait();    // ロックを解放して待機
            } catch (InterruptedException e) {
                return;
            }
        }
        n++;
        System.out.println("Inc:" + n);
        notify();          // 減算を待っているスレッドを起こす
    }

    synchronized void dec() {
        while (n == 0) {   // 下限に達している間は待つ
            System.out.println("nが0なので、減算を待機");
            try {
                wait();
            } catch (InterruptedException e) {
                return;
            }
        }
        n--;
        System.out.println("Dec:" + n);
        notify();          // 加算を待っているスレッドを起こす
    }

    public static void main(String[] args) {
        WaitNotifyTest wt = new WaitNotifyTest();
        new IncThread(wt).start();
        new DecThread(wt).start();
    }
}

class IncThread extends Thread {
    WaitNotifyTest wt;

    public IncThread(WaitNotifyTest wt) {
        this.wt = wt;
    }

    public void run() {
        for (int i = 0; i < 1000; i++) {
            wt.inc();
        }
    }
}

class DecThread extends Thread {
    WaitNotifyTest wt;

    public DecThread(WaitNotifyTest wt) {
        this.wt = wt;
    }

    public void run() {
        for (int i = 0; i < 1000; i++) {
            wt.dec();
        }
    }
}
重要wait() は必ず if ではなく while ループの中で呼ぶ

wait() から戻ったときに、待っていた条件が満たされているとは限りません。理由は2つあります。

  1. 起こされてからロックを再取得するまでの間に、別のスレッドが先に値を変えている可能性がある。
  2. Javaの仕様上、通知がなくても wait() から戻ることがある（見せかけの起床, spurious wakeup）。

while で囲んでおけば、戻った後にもう一度条件を確かめ、満たされていなければ再び待機させることができます。

6.4 まとめ

ノート待つ時間に上限を設ける

join() と wait() は、join(1000) や wait(1000) のように引数でミリ秒を指定できます。指定すると、待っている出来事（スレッドの終了や通知）が起こらなくても、指定時間が過ぎれば待機をやめます。

ただし wait() の場合は、指定時間が過ぎた後も、ロックをもう一度取得できてから、wait() の次の行から再開します。

練習問題3：条件が整うまで待つキュー

練習問題1の IntQueue を、次のように変更してください。

  • キューが空のときに dequeue() が呼ばれたら、要素が追加されるまで wait() で待つ。
  • キューが満杯のときに enqueue() が呼ばれたら、要素が取り出されるまで wait() で待つ。
  • その結果、各スレッドが必ず100回ずつ enqueue() または dequeue() を成功させるようにする。

実行結果の例

$ java IntQueue
（中略）
dequeue :22 tail:1
dequeue :80 tail:0
dequeue :47 tail:-1
dequeue :Queue Empty.. wait enqueue()
enqueue :98 tail:0
（中略）
enqueue :100 tail:8
enqueue :58 tail:9
enqueue :Queue Full.. wait dequeue()
dequeue :33 tail:8
dequeue :53 tail:7

実行結果の確認方法

  • プログラムが止まらずに終了する
  • 最後に表示される tail は -1 になる（追加と取り出しの回数が等しいため）
  • enqueue :数値 の行と dequeue :数値 の行が、それぞれちょうど200行表示される

次のコマンドで、行数を数えて確かめられます（Queue を含む行は待機の表示なので除きます）。

$ java IntQueue | grep -v Queue | grep -c '^enqueue'
200
$ java IntQueue | grep -v Queue | grep -c '^dequeue'
200
ヒントヒント（最初は自力でやってみること。クリックで表示）
  • 満杯・空のときの return を、while で条件を確かめながら wait() で待つ処理に置き換えます（セクション 6.3.4）。
  • 追加・取り出しに成功した後で、待っているスレッドを起こす処理を追加します。追加側と取り出し側が2つずつあることを踏まえて、notify() と notifyAll() のどちらを使うか選びます。
